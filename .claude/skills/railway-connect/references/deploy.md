# הפריסה הראשונה — ושלוש המלכודות כבדיקות

רץ רק כשהמשתמש מבקש לפרוס. עד אז הסקיל סיים את עבודתו בשלב 3.

**כל מלכודת כאן היא בדיקה שהסקיל מריץ, לא אזהרה שהוא מדפיס.** אזהרה
בטקסט לא מונעת כלום.

---

## הסדר

```bash
railway init --name <שם-הפרויקט>      # 1. פרויקט
railway add --service <שם-השירות>      # 2. שירות — ⚠️ נוצר ריק. ראה מלכודת 1
railway variables --set "KEY=VALUE" …  # 3. משתני סביבה (הכל חוץ מ-PORT)
railway up --detach                    # 4. בנייה והרצה — כאן מתחיל החיוב
railway domain                         # 5. כתובת ציבורית
```

**אומרים למשתמש שבשלב 4 מתחיל החיוב.** לא מפתיעים אותו בחשבון.

---

## מלכודת 1 · Empty Service — זו שמתגלה שבוע אחרי

`railway add --service` יוצר **Empty Service**, ו-`railway up` רק מעלה את
תוכן התיקייה. **בלי לחבר את הריפו לשירות, `git push` לא פורס כלום.**

התסמין: הכל עובד בהקמה. שבוע אחר כך מישהו משנה קוד, דוחף, ושום דבר לא
קורה — בלי שגיאה. הוא יחשוב שהוא שבר משהו.

**הבדיקה:**
```bash
railway service status
```
אין `source` מחובר → **מחברים**:

```bash
railway service source connect --repo <owner>/<repo> --branch main
```

**זה דורש אישור בדפדפן.** הריפו של המשתמש פרטי, ולכן ה-GitHub App של
Railway צריך גישה אליו — אישור שרק המשתמש יכול לתת.

נכשל? מסלול ידני, ואומרים אותו במלים פשוטות:

> `railway open` → ללחוץ על השירות → **Settings** → **Source** →
> **Connect Repo** → לבחור את הריפו.
> הריפו לא ברשימה? → **Configure GitHub App** → לתת ל-Railway גישה אליו →
> לחזור ולבחור.

מכאן כל `git push origin main` פורס אוטומטית, ואין יותר צורך ב-`railway up`.

## מלכודת 2 · Volume — הזיכרון שנמחק

**Railway מוחק את מערכת הקבצים של הקונטיינר בכל דפלוי ובכל restart.**
זו התנהגות מתועדת, לא באג.

התסמין: הסוכן זוכר תוך כדי שיחה, אבל **מתחיל מאפס מול כל לקוח אחרי כל
עדכון**. נראה כמו בעיה בקוד ואינו.

**הבדיקה:** האם הקוד כותב לקובץ? (`MEMORY_FILE`, `*.json`, `*.db`, `data/`)
כן → צריך Volume על הנתיב הזה.

יש נתיב כתיבה ואין Volume → **אומרים את זה לפני הפריסה**, לא אחריה.
זה הבדל בין "הכלי הזהיר אותי" לבין "הכלי איבד לי נתונים".

---

## מלכודת 3 · קישור הפרויקט שאבד

**הבדיקה:**
```bash
railway status
```
לא מקושר → `railway link` (עם `--project` / `--service` אם ידועים).

זה קורה בעיקר אחרי `railway logout`, שמוחק את קישורי הפרויקטים ולא רק את
ההזדהות. **לכן הסקיל לא מריץ logout** — ראה `auth.md`.

---

## אחרי הפריסה

1. `railway domain` → **מדפיסים את הכתובת למשתמש.** זו ההוכחה שזה עלה
2. `railway logs` → קוראים 20 שורות ומאמתים שהשירות למעלה ולא בלופ נפילות
3. עלה ומיד נפל → **ברוב המקרים זה משתנה סביבה חסר, לא הקוד.** בודקים
   קודם `railway variables` מול מה שהקוד מצפה לו

**לא אומרים "נפרס בהצלחה" בלי לוג נקי וכתובת שעונה.**
