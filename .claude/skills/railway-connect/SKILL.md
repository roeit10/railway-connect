# חיבור ל-Railway — פקודה אחת, קליק אחד

מחבר את Claude Code ל-Railway מקצה לקצה: מתקין את ה-CLI, מתקין את **ה-MCP
הרשמי של Railway** לתוך Claude Code, ומשאיר למשתמש **דבר אחד** — להתחבר
בדפדפן דרך לינק שהסקיל נותן לו.

מהרגע הזה קלוד יוצר פרויקטים, פורס, מגדיר משתני סביבה וקורא לוגים בעצמו.
**המשתמש לא לומד אף פקודה.**

---

## חוקי הפרוטוקול

**הסעיף הזה מיועד לקלוד, לא למשתמש.** הוא מגדיר את סדר ההקמה.

1. **שלב אחד בכל פעם.** אין לפתוח שלב חדש לפני שהקודם אומת.
2. **אימות = `doctor.sh`, לא הצהרה של המשתמש.** משתמש שאומר
   "התחברתי" הוא סימן להריץ בדיקה, לא לסמן וי.
3. **אין לנחש ואין להמציא ערכים.** לינק, קוד או מזהה שלא הופיע בפלט של פקודה —
   לא ממציאים.
4. **בקשה אחת בכל הודעה.** לא לשלוח למשתמש רשימה של חמישה דברים לעשות במקביל.
5. **לפני התקנה — לבקש אישור.** לומר מה מותקן ולמה, ולחכות לאישור.
6. **לא פורסים כלום עד שהבדיקה מחזירה `NEXT: READY`.**

**בכל שלב: להריץ `doctor.sh`, לקרוא את שורת ה-`NEXT`, ולעבוד על
השלב שהיא מציינת.** ההחלטה באיזה שלב אנחנו היא של הסקריפט, לא שלך.

---

## הכללים שלא נשברים

1. **צעד אנושי אחד בלבד.** ההתחברות בדפדפן היא הדבר היחיד שהמשתמש עושה.
   כל השאר — התקנה, הגדרה, אימות — עבודה של הסקיל. אם משהו נוסף דורש
   התערבות, **זה באג בסקיל, לא הוראה למשתמש.**
2. **לא מבקשים טוקן בצ'אט.** אף פעם. ההזדהות עוברת דרך `railway login` בלבד.
   אין `RAILWAY_TOKEN` שמודבק בשיחה ואין העתקה של תוכן `~/.railway/config.json`.
3. **`railway logout` — לא מריצים. בשום מצב.** הוא מוחק גם את **קישורי
   הפרויקטים** ולא רק את ההזדהות, ואז פקודות פריסה נשברות בלי שהמשתמש
   מבין למה. צריך להחליף משתמש? המשתמש מריץ בעצמו, אחרי שהסברת מה זה עושה.
4. **לא נוגעים בחיוב.** לא משדרגים תוכנית, לא מוסיפים כרטיס, לא מגדילים שירות.
5. **לא נוגעים בהגדרות ה-shell.** לא מוסיפים שורות ל-`.zshrc` ולא "מסדרים" PATH.
6. **גבולות תפקיד.** הסקיל עונה על שאלה אחת: **שיהיה חיבור עובד ל-Railway.**
   הוא לא מנהל תשתית, לא מנטר, ולא כותב את האפליקציה שתיפרס.

## STEP 1 · התקנת ה-CLI

המטריצה המלאה ב-`references/install.md`.

**לפני שמתקינים — לומר מה מותקן ולמה, ולחכות לאישור** (חוק 5):

> ה-Railway CLI לא מותקן. הוא מה שמאפשר לי להעלות דברים לשרת ולקרוא לוגים
> בשבילך. מתקין?

אחרי אישור — **מזהים את המערכת ולא שואלים את המשתמש מה יש לו**:

| מערכת | פקודה |
|---|---|
| macOS / Linux / WSL | `curl -fsSL agents.railway.com \| sh` |
| macOS — חלופה | `brew install railway` |
| Windows | `npm i -g @railway/cli` |

**גרסה מתחת ל-5.44.0** → משדרגים באותה דרך שבה הותקן. לפני זה
`railway mcp install` לא קיים, וזה נראה כמו `unrecognized subcommand`.

סוגרים את השלב ב-`doctor.sh`.

## STEP 2 · ההתחברות · הצעד האנושי היחיד

**קרא את `references/auth.md` לפני שאתה מריץ.** שם הפלט המדויק והפרסור.

**אין חשבון?** קודם שולחים את קישור ההזמנה —
`https://railway.com?referralCode=qSz7aA` (20$ קרדיט מתנה) — וממליצים
להירשם **עם אותו חשבון GitHub**, כי זה מקצר את חיבור הריפו בהמשך.
למי שיש — מדלגים ישר להתחברות.

```bash
railway login --browserless > "$OUT" 2>&1 &     # ברקע. הפקודה ממתינה ולא חוזרת
```

מחלצים מהפלט את הלינק ומגישים אותו:

```
🔗 להתחברות בקליק אחד:
   https://railway.com/activate?user_code=XXXX-XXXX

תפתח, תאשר, וזה הכל — הקוד כבר בתוך הלינק.
אני בודק לבד מתי זה נסגר, אין צורך לעדכן אותי.
```

ואז **בודקים בלופ** (חוק 2 — לא שואלים "סיימת?" ומחכים לתשובה):

```bash
for i in $(seq 1 40); do
  railway whoami --json >/dev/null 2>&1 && break
  sleep 3
done
```

- הצליח → מדפיסים את המייל שהתחבר. **נגמר הצעד האנושי.**
- נגמר הזמן → **לא מנחשים שזה עבד.** אומרים שהחיבור לא אומת, ומציעים
  למשתמש להריץ `railway login` בטרמינל שלו — שם הדפדפן נפתח ישר.

סוגרים את השלב ב-`doctor.sh`.

## STEP 3 · התקנת ה-MCP לתוך Claude Code

```bash
railway mcp install --agent claude-code
```

זו הפקודה הרשמית של Railway, והיא כותבת את הקונפיג בעצמה. **לא כותבים
`.mcp.json` ביד** — קונפיג שנכתב ידנית נשאר מאחור כשהם משנים את הפרוטוקול.

| דגל | מתי |
|---|---|
| ברירת מחדל (`--remote`) | פרוקסי דרך ה-CLI ל-`mcp.railway.com`, מזדהה דרך ההתחברות מ-STEP 2. **זה מה שרוצים** |
| `--local` | ה-MCP המקומי. יותר כלים (משתני סביבה, דומיינים, ווליומים, תצפית) — להציע רק אם המשתמש נתקל בחסר |
| `--oauth` | OAuth ישר, בלי CLI. לא הנתיב שלנו |

> יש גם `railway setup agent` שעושה התקנה **וגם** התחברות בצעד אחד — אבל הוא
> אינטראקטיבי, ולכן הסקיל מפצל: התחברות ב-STEP 2 (שם צריך את הלינק),
> והתקנה כאן.

**אימות ב-`doctor.sh`.** לא נרשם → אומרים שזה נכשל, לא "כנראה שעבד".

**ואז אומרים למשתמש את הדבר האחד שנשאר: להפעיל מחדש את Claude Code.**
MCP חדש נטען בעלייה. בלי זה הכלים לא יופיעו והוא יחשוב שנשבר.

## STEP 4 · גיטהאב — לפי צורך, לא כברירת מחדל

**הפרטים ב-`references/github.md`.**

**גיטהאב אינו תנאי לחיבור ל-Railway**, ולכן `NEXT: READY` נסגר גם בלעדיו.
הוא נדרש לדבר אחד: **שכל `git push` יפרוס**.

| מה המשתמש רוצה | צריך גיטהאב? |
|---|---|
| "תפרוס לי את התיקייה הזאת" | ❌ `railway up` מעלה ישירות |
| **"שכל push יפרוס"** · תבנית (`Use this template`) | ✅ |

**מריצים את השלב הזה כשמגיעים לצורך**, לא לפניו — כדי לא לכפות על המשתמש
צעד אנושי שני שהוא אולי לא צריך (חוק 1: **צעד אנושי אחד בלבד**).

```bash
gh auth login --hostname github.com --git-protocol https --web --scopes "repo,workflow" > "$OUT" 2>&1 &
```

⚠️ **ההגשה שונה מ-Railway.** שם הקוד מוטמע בלינק; **בגיטהאב הוא נפרד**:

```
🔢 העתק את הקוד:   XXXX-XXXX
🔗 ואז פתח:        https://github.com/login/device
```

**הקוד ראשון, הלינק שני.** מי שפותח את הדף לפני שהעתיק — יצטרך לחזור.

מבקשים `workflow` יחד עם `repo` **מראש**, כי בלעדיו דחיפת `.github/workflows/`
נדחית בהודעה שנראית כמו בעיית הרשאות בריפו ואינה.

## DEPLOY · הפריסה הראשונה, ושלוש המלכודות

רק כשהמשתמש מבקש לפרוס, ורק אחרי `NEXT: READY` (חוק 6).
**הפירוט המלא ב-`references/deploy.md`** — ושם כל מלכודת היא **בדיקה שהסקיל
מריץ**, לא אזהרה שהוא מדפיס:

| # | המלכודת | הבדיקה |
|---|---|---|
| 1 | `railway add --service` יוצר **Empty Service**. בלי לחבר את הריפו לשירות, `git push` **לא פורס כלום** — מתגלה שבוע אחרי | `railway service status` → יש `source` מחובר? |
| 2 | **Railway מוחק את מערכת הקבצים בכל דפלוי ובכל restart.** כל דבר שנשמר לקובץ נעלם | הקוד כותב לקובץ? → יש Volume על הנתיב? |
| 3 | קישור פרויקט אבד → פקודות פריסה נשברות | `railway status` → מקושר? אחרת `railway link` |

**מלכודת 1 דורשת גיטהאב מחובר** (`STEP 4`) **ואישור בדפדפן** — ה-GitHub App
של Railway צריך גישה לריפו הפרטי. הריפו לא ברשימה? **Configure GitHub App** →
לתת גישה → לחזור.

> `gh` לא מחובר ומגיעים לכאן → **עוצרים ומריצים את `STEP 4`**, ורק אז ממשיכים.

**אומרים למשתמש שב-`railway up` מתחיל החיוב.** לא מפתיעים אותו בחשבון.

## אם משהו נשבר

| מה קרה | מה עושים |
|---|---|
| `railway: command not found` אחרי התקנה | ה-PATH לא רוענן. לנסות נתיב מלא, ולהגיד למשתמש לפתוח טרמינל חדש |
| `mcp install` לא קיים | גרסה מתחת ל-5.44.0. לשדרג |
| `whoami` מחזיר שגיאת הרשאה | ההתחברות פגה. חוזרים ל-STEP 2. **לא מריצים logout** |
| הכלים לא מופיעים בקלוד | לא הופעל מחדש. זה הדבר הראשון לבדוק |
| הפריסה עולה ומיד נופלת | `railway logs` — ברוב המקרים משתנה סביבה חסר, לא הקוד |
| `git push` נדחה על `workflow scope` | חסר scope. `gh auth refresh -h github.com -s workflow` |
| הדוקטור אמר שיש `workflow` אבל push נדחה | נבדק החשבון הלא נכון. `gh auth status --active` הוא הקובע |
